## Statement

Make verification of the core web and iOS journeys reproducible and required in CI.

- Run the Playwright browser suite (apps/web/e2e, local stack with the Auth emulator) as a CI job in .github/workflows/ci.yml, listed in the `needs` of the aggregating "All gates" job, and cover garden creation, map editing, plants, observations, and tasks.
- Make "All gates" a required status check in branch protection for `master`, and record the resulting protection state with its verification date in repository documentation.
- Add the first native iOS UI test (simulator) for creating the first garden. It runs in the existing `swift` CI job, under the same change-detection filter as that job (apps/ios/** and its existing companions), so it is part of "All gates" whenever that job runs.
- Verify the already fixed GG-0003, GG-0005, and GG-0007 by hand in a browser against deployed development. Record each result as a dated row in the issue's Observations table, including the web version. Close an issue only when its own criteria pass; an issue that fails stays open with the failing observation recorded. Fixing a failure is outside this feature.

## Acceptance Criteria

- [x] The CI workflow has a Playwright job that runs the browser suite, and "All gates" lists that job in `needs`, so a failed or cancelled Playwright run makes "All gates" fail.
- [x] The browser suite has passing specs for garden creation, map editing, plants, observations, and tasks, and each spec runs in the CI Playwright job.
- [x] Branch protection on `master` requires the "All gates" check. A pull request with a red "All gates" cannot be merged, and the dated record of this setting exists in repository documentation.
- [x] The iOS project has a UI test target with a first-garden creation test, and the `swift` CI job runs that test on a simulator and fails when it fails.
- [x] A change under apps/ios/** triggers the iOS UI test in CI. A change that touches no path in the `swift` filter skips it, and "All gates" still passes.
- [x] Each of GG-0003, GG-0005, and GG-0007 has a new Observations row recording the date, "Web <version>, deployed development", the expected result, the actual result, and reproducibility from a manual browser check.
- [x] Each of the three issues is closed only if that observation shows that all of its own acceptance criteria pass. Otherwise it stays open.
