# F-002 - Existing browser acceptance detects excluded GG-0005 failure

## Evidence

Local complete run on 2026-10-04: 52 passed, one failed. The existing
`responsive.spec.ts` phone-canvas test expects one visible tabpanel and receives
two. The geometry, toolbar, zoom, explicit tabs, and all named core journeys pass.
This is consistent with the manual deployed GG-0005 Backdrop leakage observation.

The cause is `.panelComfort { display: flex; }` in
`map-inspector-drawer.module.css`: author CSS overrides the user-agent hidden
rule for the Backdrop tabpanel. The component already sets `hidden` correctly
and deliberately keeps all panels mounted to preserve in-flight uploads.
A proposed `.panel[hidden] { display: none; }` rule would restore visibility
without changing mounting or adding a new GG-specific browser assertion. It has
not been applied: the failure remains outside the authorized fix scope.

## Resolution

A direct audit of REQ-001 acceptance criteria and implementation plan I-1, I-2,
and I-6 found no contradiction. Passing specs are required for the five named
core journeys; all existing browser specs must execute and their failures must
block merging. Neither record requires R02 to fix all failures found by that
gate. The responsive Backdrop assertion is retained and continues to fail, as
recorded in the open GG-0005 issue. No GG-specific assertion or fix is added.

Q-004 was withdrawn without a user answer or an exception to the recorded
decision. R02 completion requires hosted passing evidence for the named core
journeys and the remaining operational acceptance; it does not authorize a
merge of this red PR or closure of GG-0005.
